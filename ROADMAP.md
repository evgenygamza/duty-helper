Из остальных каналов Slack событий не шлёт — это забирает Э4.

- [x] каркас на `slack_bolt` + Socket Mode, точка входа `bot/app.py`
- [x] слушатель `@app.message` с регуляркой на тег группы
- [x] пересылка в канал очереди со ссылкой на исходное сообщение
- [x] документация Bolt подтянута в `temp/bolt-docs/`

**Выход:** призыв в известном канале появляется в ленте за секунды.
Проверено 31.08: призыв в `#channel-with-bot` доехал в `#duty-feed`,
такой же призыв в `#channel-without-bot` не доехал — событий оттуда нет.

## Проверено в песочнице

Приложение `duty-helper`, бот `dutyhelper` (`U0BS4J84MMM`),
группа `@qa-factset-dutyman` = `S0BTF0KMJV6`.

Каналы: `#channel-with-bot` `C0BSKTQ1M5G`, `#channel-without-bot` `C0BTSTZ2J3X`,
`#duty-feed` `C0BTQL7AK4K`.

- поиск группы работает, если в запросе есть `@`: `@qa-factset-dutyman`
  находит настоящие теги `<!subteam^ID>`, без `@` — только текстовые вхождения
- user-токен читает треды: `conversations.replies` отвечает. Но канал был тот,
  где бот состоит, — чтение без членства ещё не доказано
- `channels:leave` у ботов не бывает: приложение не может выйти из канала.
  Канал без бота создаётся user-токеном с правом `channels:write`
- подписка на `app_mention` требует scope `app_mentions:read`, иначе
  `apps.manifest.validate` не пропускает манифест
- манифест берётся через хук `get-manifest` из `.slack/hooks.json`; хук по
  умолчанию ищет файл `manifest.json`
- работают `chat.update`, `chat.delete`, `reactions.add/remove`,
  `slackLists.create`, `items.create`, `items.list`, `items.info`
- `slackLists.items.update` → `invalid_arguments`
- `assistant.search.context` → `invalid_action_token`: метод для ассистентов
  Slack, не наш путь
