## Э1 — сбор

Бот собирает призывы и пересылает их в отдельный канал. Два пути, оба нужны:
Slack присылает боту события только из каналов, где бот состоит, а вступить
во все нельзя.

### 1а — из известных каналов, мгновенно

- [ ] каркас на `slack_bolt` + Socket Mode
- [ ] бот вступает в каналы команды, список — в конфиге
- [ ] событие `message.channels` с тегом группы → пересылка в канал очереди

**Выход:** призыв в известном канале появляется в очереди за секунды.

### 1б — отовсюду, с задержкой

- [ ] поиск user-токеном `@qa-factset-dutyman -in:<шумные> -from:<боты>
      after:<точка>`, раз в минуту
- [ ] дедуп: не пересылать то, что уже переслали и что поймали событием
- [ ] проверить чтение треда в канале, где бота нет — на Э0 не доказано

**Выход:** призыв из любого канала доезжает за минуту.

## Проверено в песочнице

Приложение `duty-helper`, бот `dutyhelper` (`U0BS4J84MMM`), канал `C0BSKTQ1M5G`,
группа `@qa-factset-dutyman` = `S0BTF0KMJV6`.

- поиск группы работает, если в запросе есть `@`: `@qa-factset-dutyman`
  находит настоящие теги `<!subteam^ID>`, без `@` — только текстовые вхождения
- user-токен читает треды: `conversations.replies` отвечает. Но канал был тот,
  где бот состоит, — чтение без членства ещё не доказано
- каналов в песочнице всего три: `all-sandbox`, `new-channel`, `social`.
  Обращения лежат в `new-channel`, по два экземпляра каждое
- подписка на `app_mention` требует scope `app_mentions:read`, иначе
  `apps.manifest.validate` не пропускает манифест
- манифест берётся через хук `get-manifest` из `.slack/hooks.json`; хук по
  умолчанию ищет файл `manifest.json`
- работают `chat.update`, `chat.delete`, `reactions.add/remove`,
  `slackLists.create`, `items.create`, `items.list`, `items.info`
- `slackLists.items.update` → `invalid_arguments`
- `assistant.search.context` → `invalid_action_token`: метод для ассистентов
  Slack, не наш путь
