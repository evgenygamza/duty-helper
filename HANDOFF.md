# Помощник дежурного FactSet — где мы остановились

Состояние на 25.08.2026.

## ТЗ

Бот в Slack, работающий **в реальном времени**:

1. собирать упоминания по пространству
2. читать тред целиком
3. превращать обращение в элемент списка, саммari пишет ИИ
4. реагировать на нажатия в списке
5. писать комментарии к элементу

Всё остальное в этом репозитории — правила дежурства, пороги, определение
просадок — существует, чтобы боту было чем наполнять список. Смысл и логика
дежурства: `skill/SKILL.md` и `skill/references/duty-channel.md`.

## Целевая архитектура

```
Slack (события по вебсокету)
   ↓ message.channels / message.groups / reaction_added
бот на Socket Mode — постоянный процесс, публичный адрес не нужен
   ↓ прочитать тред → ИИ пишет саммари
slackLists.items.create — элемент в трекере
   ↓ человек меняет статус или ставит 🎫
реакция бота: комментарий в тред элемента, инцидент в ITSM, закрытие
```

**Сбор упоминаний идёт поиском, а не событиями.** Тегнуть могут в любом канале,
списка «нужных» не существует, а события приходят боту только оттуда, где он
состоит. Вступать во все публичные каналы подряд нереально: это тысячи записей
«duty-helper joined» и отдельный разговор с админами.

Поэтому:

- **поиск user-токеном** — основной механизм. Видит всё, где состоит человек,
  без вступлений. Реальное время достигается частотой: `search.messages` с
  `after=<последняя точка>` раз в минуту даёт задержку меньше минуты при
  регламенте в час
- **события** — только для действий в трекере: реакции-кнопки и изменения
  элементов прилетают из `#factset-duty`, где бот и так сидит. Socket Mode нужен
  для этого, а не для сбора

Поиск это ровно тот механизм, которым сейчас пользуется скилл:
`search.messages` с запросом `qa-factset-dutyman -in:<шумные> -from:<боты>
after:<точка отсчёта>`. Боту он доступен через `xoxp`, который выдаётся при
установке приложения — в манифесте `search:read` уже есть. Бот-токен воркспейс
не ищет, это ограничение Slack, а не прав.

User-токен действует от имени установившего приложение: бот увидит то же, что
видит человек, и действия пойдут от его лица.

Запускать скилл через `claude -p` из бота — только как временная затычка:
логика готова, но каждый вызов это десятки секунд и целая сессия, а в кубере
Claude Code нет вовсе.

## Открытые вопросы

- **события списков.** Прямых событий Events API для Lists не нашлось. Обходы:
  воркфлоу с триггером «элемент изменился» плюс вебхук, либо опрос `items.list`.
  Проверить в песочнице, что реально приходит при смене статуса
- **комментарии к элементу.** У каждого элемента свой тред; как в него писать
  через API — не проверено
- **где живёт бот.** Socket Mode не требует адреса, но требует процесса: сначала
  локально, потом контейнер в кубере через argocd, как остальной стек

## Как править приложение

Редактора манифеста в вебе **нет**: приложение создано как CLI-приложение, у
таких манифест лежит файлом в проекте. Поэтому либо руками через интерфейс
(OAuth & Permissions → Scopes, Socket Mode → тумблер, Event Subscriptions →
bot events), либо через Slack CLI:

```
curl -fsSL https://downloads.slack-edge.com/slack-cli/install.sh | bash
slack login
```

Второй путь предпочтительнее: манифест становится частью репозитория, а из
шаблона [agent-quickstart](https://docs.slack.dev/ai/agent-quickstart/) сразу
получается каркас бота на Bolt с Socket Mode — то есть именно то, что нужно по
ТЗ. Первый путь придётся переделывать.

## Ближайшие шаги

1. переустановить приложение с новым манифестом
2. забрать user-токен, дописать в `~/.config/duty-helper/sandbox.env`
3. добить схему `items.update` и механику комментариев
4. поднять бота на Socket Mode локально, поймать первое событие
5. собрать цепочку целиком: упоминание → тред → элемент списка с саммари
