# Скрипты портала: их здесь нет

Вход в Issue Tracker поставщика идёт под личной учёткой человека: headless-браузер,
пароль, одноразовый код из почты, селекторы чужих форм. Всё это живёт в скилле
`factset-letters` и только там — бот их зовёт, но не хранит. Причин две: копии уже
начали разъезжаться, а репозиторий бота открыт.

Бот ищет каталог со скриптами в таком порядке:

1. настройка `vendor.scripts` в `duty.toml` (она же `DUTY_PORTAL_SCRIPTS`)
2. `~/.claude/skills/factset-letters/scripts`

Чего бот ждёт от этого каталога — четыре скрипта, каждый запускается через
`uv run --script`:

| скрипт | вызов | что отдаёт |
|---|---|---|
| `login.py` | без аргументов | обновляет файл с куками; на выходе печатает, чем кончилось |
| `issues.py` | `moves <uuid> …` или `moves --open` | JSON: `uuid`, `title`, `status`, `last_on`, `last_by`, `by_factset`, `comments` |
| `reply.py` | `<uuid> --body-file <html>` | ответ в существующее обращение |
| `create.py` | `--subject … --body-file … --content-set …` | новое обращение |

Общий контракт один: если сессия умерла, скрипт печатает `session has expired`
и завершается — по этой строке `session.py` понимает, что пора логиниться заново.

Без каталога бот работает, но без вендорской части: проверка «ответил вендор»
и карточки из трекера скажут в ленту, что скриптов нет.
