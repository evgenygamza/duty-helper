# Как запустить бота локально

На проде будет контейнер, это только для разработки.

Работаем в песочнице **`duty-helper`**, Enterprise-орг `E0BU1D8791B`,
воркспейс внутри — `T0BU98BAB5J`. Приложение `A0BU7PW74C9`.
Прежняя песочница `sandbox-d879184` заброшена: она бесплатная, и custom steps
на ней невозможны.

## Запуск

```bash
export PATH="$HOME/.local/bin:$PATH"
cd ~/Projects/duty-helper/bot
set -a; . ~/.config/duty-helper/duty-helper.env; set +a
export PYTHONUNBUFFERED=1
slack run -w E0BU1D8791B --org-workspace-grant T0BU98BAB5J --hide-triggers \
  > /tmp/duty-bot.log 2>&1 &
```

Через полминуты в логе должно быть `⚡️ Bolt app is running!` и строка
`board F0C0RB7157H: N columns` — схему колонок бот читает при старте.

Почему так, а не `python app.py`:

- **`slack run`** сам подставляет `SLACK_BOT_TOKEN` и `SLACK_APP_TOKEN`, поэтому
  токены нигде не лежат. Он же переустанавливает приложение при старте, так что
  правка `manifest.json` доезжает сама, и следит за файлами — правку кода
  подхватывает перезапуском
- **`PYTHONUNBUFFERED=1`** обязателен: без него лог отстаёт на минуты, живой
  бот выглядит мёртвым, и диагностика превращается в гадание. Проверено дважды

## Пересоздание доски

Колонки задаются только при создании списка, поэтому новая колонка означает
новую доску. Порядок такой:

0. остановить бота: он пишет в старую доску до последнего прохода
1. создать новую, вписать её id в `DUTY_LIST_ID`, и **дать ей имя с датой**:
   `slack api slackLists.update --app local -w E0BU1D8791B --json
   '{"id":"<новый id>","name":"Очередь дежурного FactSet · с ДД.ММ"}'`.
   Одинаковые имена и были причиной путаницы: в сайдбаре доски не отличить
2. **старую удалить сразу**: `slack api files.delete --app local -w E0BU1D8791B
   file=<старый id>`. Метода `slackLists.delete` не существует
3. дать ссылку на новую в чат: `files.info` отдаёт `permalink`
4. перенести карточки: у новой доски свои id колонок, поэтому перенос
   значит «прочитать старые `items.list` и создать заново». Заодно заполнить
   реестр: `Ledger.book` = `{id новой карточки: 'статус@ts|прочитано'}`,
   и `_save()`
5. выдать каналу `write` (`slackLists.access.set`) — иначе доску видит
   только бот
6. переставить закладку в `#duty-feed`. Прочитать её ботом нельзя —
   `bookmarks.list` отдаёт ему пустой список даже с `bookmarks:read`, —
   так что новую закладку бот добавит, а старую снимет человек

Реестр бухгалтерии живёт отдельно от доски — закреплённым сообщением
в `#duty-feed`, — и пересборку переживает. Чистить его не надо: карточки,
которых нет на доске, он забывает сам.

Пункт 2 не про порядок, а про то, что живая мёртвая доска обманывает: воркфлоу
пять дней смотрел на удалённый список, и заметить это было нечем.

## Остановка и лог

```bash
pkill -f "slack run"          # остановить
pgrep -fl "slack run"         # проверить, жив ли
tail -f /tmp/duty-bot.log     # смотреть лог
```

Лог перезаписывается при каждом запуске — если нужен прошлый, копируй до старта.
`pgrep -fl app.py` теперь ничего не находит: процесс запускается под `slack run`.

## Что должно быть в окружении

Один файл, `~/.config/duty-helper/duty-helper.env`, права 600, лежит вне
репозитория:

```
DUTY_GROUP_ID=S0BV0EVS7ME
DUTY_FEED_CHANNEL=C0BU7RTJCDP
DUTY_LIST_ID=F0C0RB7157H
GEMINI_API_KEY=...
SLACK_USER_TOKEN=xoxp-...     поиск и отметки в каналах без бота
DUTY_SWEEP_SECONDS=15         сейчас тестовое, рабочее около 120
DUTY_SEARCH_FILTER=           модификаторы поиска, пусто = не отсекаем
DUTY_SEND_OUTWARD=            письма и инциденты наружу; пусто = заглушка
DUTY_USER_ID=                 кому напоминания; пусто = состав группы
DUTY_SINCE=                   с какого момента бот считает историю своей
DUTY_DRY_RUN=                 смотрю и ничего не трогаю; пусто = работаем
```

**`DUTY_SINCE` стоит задавать датой, а не оставлять пустым.** Пусто означает
«история начинается с этого запуска», и тогда каждый перезапуск сдвигает черту:
призывы, пришедшие пока бот лежал, не попадут на доску вовсе. Дата держится
на месте — `DUTY_SINCE=2026-09-14` или `30d`. Всё, что старше черты, обход
оставляет в покое и говорит об этом в лог. Окно поиска тоже считается от неё,
плюс сутки запаса.

**`DUTY_DRY_RUN=1` для первого прогона в живом воркспейсе.** Бот читает всё
как обычно, но ни одной записи не делает: в лог идут строки «завёл бы
карточку», «свёл бы отметки», «написал бы в личку», а числа в отчёте прохода
означают «сделал бы столько». Модель при этом не зовётся вовсе.

`DUTY_SEND_OUTWARD` выключен по умолчанию намеренно. При нём «отправляй»
и «заводи» пишут то, что ушло бы, в файл и называют путь в треде, а к вендору
и в Jira ничего не уходит.

Обязательны только первые три и `GEMINI_API_KEY`. Без `SLACK_USER_TOKEN`
бот стартует, но обход видит лишь каналы, где бот состоит, — в лог уходит
предупреждение.

Слаковских токенов здесь нет и быть не должно: их подставляет `slack run`.
Соседний `sandbox.env` — от заброшенной песочницы, больше не используется.

Бот отказывается стартовать, если чего-то не хватает, и называет чего именно.

## Проверить, что живой

Тегнуть `@qa-factset-dutyman` в `#channel-with-bot` (`C0BU5TL051Q`) — через
несколько секунд в логе появится `item ... created`, на доске новая карточка.

Отметки в треде: подвигать статус карточки на доске и дождаться следующего
прохода — в отчёте обхода вырастет `отметок`, а `часы` покажет, что бот
заметил смену статуса. Мгновенно этого не будет: воркфлоу и custom step
выброшены 10.09, а событий Slack Lists не рождают.

Разовая грабля переезда: пока у Slack был установлен манифест с блоком
`functions`, а в репозитории уже без него, `slack run` считал это breaking
change и ждал подтверждения в интерактиве, то есть в фоне падал. Лечится
одним запуском с `--force`. После него установленный манифест сходится
с файлом, `manifest validate` отвечает `Valid` без предупреждений,
и флаг больше не нужен.

`/duty`: набрать в любом канале. Без аргумента бот отвечает, кто в группе
и кому идут напоминания — ответ видит только тот, кто спросил. `/duty @имя`
переписывает группу на этих людей — их может быть несколько, `/duty @я @сменщик`
кладёт в группу обоих, — и об этом появляется строка в `#duty-feed`.
Пока не открыто право на запись группы, второй вариант честно отвечает, каких
прав не хватает. Выбирать человека надо из подсказки Slack, иначе в текст
команды приедет строка, а не id, и бот скажет, что не понял.

Напоминания: в отчёте прохода поле `напомнил`. Чтобы проверить, не ожидая
получаса, вписать карточке статус `new` и время получасовой давности прямо
в ячейку — обход напишет в личку и на следующем проходе повторять не станет.

Обход: идёт на старте и каждые `DUTY_SWEEP_SECONDS` секунд, сейчас 15 —
это тестовое значение, рабочее около 120. **Поиск по всему воркспейсу идёт
своим темпом, раз в минуту** (`SEARCH_EVERY` в `sweep.py`): индекс Slack
отстаёт секунд на двадцать, и запрос идёт под личным токеном человека.
Тред, в котором написали **без тега**, подхватывает только он: событий на такое
Slack не присылает, поэтому интервал и есть время реакции. Уменьшать дальше
мешает лимит Slack — `conversations.replies` это один запрос на карточку
за проход, а лимит около пятидесяти в минуту.
Итог одной строкой:

```
sweep: карточек 3, отметок 2, новых 0, освежил 0 из 0, висит 0, за 2.5с
```

Проход без модели укладывается в секунды, каждая новая или отставшая карточка
добавляет 15-20 секунд на модель. Перезапуск бота — самый быстрый способ
прогнать обход, не дожидаясь таймера.

Если модель отвалилась или упёрлась в квоту, бот напишет в `#duty-feed`
«не смог завести карточку» со ссылкой на тред. Пустой лог и тишина в канале
означают, что событие не дошло вовсе.

**Бесплатный тир Gemini — 20 запросов в минуту, не в сутки.** В теле `429`
метрика `generate_content_free_tier_requests, limit: 20` и «Please retry in
3s». Пачка новых карточек подряд может упереться, но отпускает через секунды
и следующий проход добирает остальное. Что не доехало, падает в `#duty-feed`.

## Вызовы API руками

Своего токена нет, поэтому через CLI — он подставляет ботовый:

```bash
slack api <method> --app local -w E0BU1D8791B key=value
slack api <method> --app local -w E0BU1D8791B --json '{"...": "..."}'
```

Формой `key=value` работает не всё: `usergroups.list` требует `team_id`
именно так, а `--json` ей отвечает `missing_argument`.

## Правка прав приложения

```bash
export PATH="$HOME/.local/bin:$PATH"
cd ~/Projects/duty-helper/bot
# поправить manifest.json, затем проверить и поставить:
slack manifest validate --app A0BU7PW74C9 -w E0BU1D8791B
slack install -E local -w E0BU1D8791B --org-workspace-grant T0BU98BAB5J --force
```

`--force` обязателен: без него CLI хочет подтверждения в интерактиве.
При обычном `slack run` переустановка происходит сама, отдельная команда нужна
только чтобы поставить манифест без запуска.
