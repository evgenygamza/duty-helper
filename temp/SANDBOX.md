# Песочница Slack: что проверяем и зачем

Обычный бесплатный воркспейс не годится: списков там нет совсем, канвасы только
на чтение, Workflow Builder тоже платный. Нужна именно **developer sandbox** —
бесплатное окружение уровня Enterprise Grid, где доступны все функции, а ты сам
себе админ и не ходишь за аппрувом на каждый scope.

## Как завести

1. Зарегистрироваться в Slack Developer Program: `api.slack.com` → Developer
   Program. Регистрация бесплатная
2. Запросить sandbox — выдают сразу, живёт полгода с продлением, можно держать
   две штуки, до трёх воркспейсов и восьми пользователей внутри
3. Создать приложение: `api.slack.com/apps` → From scratch, выбрать sandbox
4. Bot Token Scopes выставить сразу все, чтобы не переустанавливать по кругу:

   ```
   chat:write            писать, править и удалять свои сообщения
   im:write              открывать личку для пинга
   reactions:read        видеть реакции
   reactions:write       ставить и снимать
   lists:read            читать списки
   lists:write           создавать списки и элементы
   channels:history      читать публичные каналы
   groups:history        читать приватные
   channels:join         вступать в публичные каналы самому
   users:read            находить людей
   users:read.email      находить по рабочей почте
   usergroups:read       состав групп
   usergroups:write      менять состав — на случай возврата к ротации
   ```

5. Install to Workspace, забрать `xoxb-...`
6. Создать тестовый канал и пригласить туда бота: `/invite @<имя-приложения>`

## Что проверяем

```
export SLACK_SANDBOX_TOKEN=xoxb-...
python3 sandbox_check.py C0123456789
```

Скрипт по очереди дёргает всё, чего не умеет claude.ai-коннектор, и печатает
карту «работает / не хватает прав». Проверяются:

- **правка и удаление своих сообщений** — из-за их отсутствия инбокс уехал на
  канвас; если заработает, вариант с сообщениями снова в игре
- **снятие реакции** — без него статус-эмодзи накапливаются, а не сменяются
- **пинг в личку** — главное, чего не может коннектор: своё же сообщение Slack
  не подсвечивает
- **создание списка и элементов** — трекер, ради которого всё затевалось
- **чтение групп** — на случай возврата к ротации `@qa-factset-dutyman`

Схема полей у `slackLists.items.create` по докам неочевидна, поэтому скрипт
печатает ответ целиком: из него и станет понятно, какие поля требуются.

## Что песочница не проверит

Данных там нет. Обращения придётся выдумывать, рабочие каналы не подтянуть,
Jira не подключить. То есть песочница отвечает на вопрос «схема технически
рабочая?», а не «инструмент полезен?». Польза проверяется только теневым
дежурством на живых данных.

## Зачем это перед походом за токеном

В `#team-it` приходят с просьбой выдать права. Разница между «хочу попробовать
идею» и «вот собранный трекер, вот список scopes, каждый нужен вот для этого» —
это разница между неделей переписки и одним аппрувом. Список scopes уже
собран в `../bot/SLACK-APP.md`.
